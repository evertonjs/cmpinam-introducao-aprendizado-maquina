O problema: como saber se o modelo generaliza?

Um modelo não deve apenas memorizar os dados que já viu. Ele precisa funcionar bem em dados novos.

Ideia fundamental

Separar dados em treino e teste ajuda a estimar como o modelo se comportará quando receber dados que ainda não conhece.

Treino Teste
Ponto-chave: avaliar no mesmo dado usado para treinar pode dar uma falsa impressão de desempenho.
2

A divisão treino/teste é útil, mas pode variar muito

Uma única divisão dos dados pode favorecer ou prejudicar um modelo por acaso.

Holdout simples

No método holdout, separamos uma parte para treino e outra para teste. Isso é simples e muito usado.

  • Exemplo: 70% treino e 30% teste.
  • Problema: outra divisão poderia gerar outro resultado.
  • Em bases pequenas, essa variação pode ser grande.
3

O que não podemos fazer: treinar e testar nos mesmos dados

Quando a avaliação usa informação que já participou do treinamento, temos uma estimativa otimista demais.

Data leakage

Data leakage ocorre quando informações do conjunto de teste acabam influenciando o treinamento.

Consequência: o modelo parece melhor do que realmente é, pois foi avaliado com informação que não deveria conhecer.

Isso está diretamente ligado ao risco de overfitting: o modelo aprende padrões específicos dos dados de treino, mas não generaliza bem.

4

A ideia da validação cruzada

Em vez de depender de uma única divisão, usamos várias divisões. Cada parte dos dados será usada como teste uma vez.

Cross Validation

A validação cruzada divide os dados em partes chamadas folds. Em cada iteração, alguns folds treinam o modelo e um fold avalia o desempenho.

Erro médio = média dos erros obtidos em cada fold
5

Exemplo visual: 3-Fold Cross Validation

Com 3 folds, fazemos 3 iterações. Em cada uma, um fold diferente é usado como teste.

Resultado: ao final, temos três medidas de erro/desempenho. A média dessas medidas é uma estimativa mais estável do desempenho do modelo.
6

Por que isso ajuda?

A validação cruzada reduz a dependência de uma única escolha de treino/teste.

Uso melhor dos dados

Todos os exemplos participam do treino em algumas iterações e do teste em outra.

Estimativa mais robusta

A média dos resultados reduz o efeito de uma divisão específica que pode ter sido sorteada.

Comparação mais justa

Modelos diferentes podem ser comparados usando as mesmas divisões.

7

Usando validação cruzada para comparar modelos

Podemos comparar modelos diferentes observando o desempenho médio em várias divisões dos dados.

Comparação correta

Um modelo muito flexível pode se ajustar bem ao treino, mas errar em dados novos. A validação cruzada ajuda a perceber isso.

Modelo linear Modelo flexível
Ideia: escolhemos o modelo com melhor desempenho médio nos folds, não apenas o que mais se ajusta aos dados de treino.
8

10-Fold Cross Validation

Quando temos uma quantidade razoável de dados, uma escolha comum é usar 10 folds.

Como funciona?

Embaralhar os dados

Quando apropriado, embaralhamos a ordem dos exemplos.

Dividir em 10 partes

Cada parte é um fold.

Repetir 10 vezes

Em cada repetição, 9 folds treinam e 1 fold testa.

Calcular a média

A média dos resultados representa o desempenho estimado.

9

Leave-One-Out Cross Validation

No Leave-One-Out, cada exemplo individual vira teste uma vez.

Quando usar?

O LOOCV pode ser útil quando a base é muito pequena, mas costuma ser mais custoso, porque treina o modelo muitas vezes.

  • Se há n exemplos, são feitos n treinamentos.
  • Em bases maiores, 5-Fold ou 10-Fold costuma ser mais prático.
  • Em classificação, muitas vezes usamos StratifiedKFold.
10

Como isso aparece no Scikit-Learn?

Na prática, usamos funções prontas para calcular os resultados em cada fold.

Regressão

from sklearn.model_selection import cross_val_score
from sklearn.linear_model import LinearRegression

modelo = LinearRegression()
scores = cross_val_score(
    modelo,
    X,
    y,
    cv=5,
    scoring="r2"
)

print(scores)
print(scores.mean())

Classificação

from sklearn.model_selection import StratifiedKFold
from sklearn.model_selection import cross_val_score
from sklearn.tree import DecisionTreeClassifier

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
modelo = DecisionTreeClassifier(random_state=42)

scores = cross_val_score(
    modelo,
    X,
    y,
    cv=cv,
    scoring="f1_macro"
)

print(scores.mean())
Observação: em classificação com classes desbalanceadas, a validação estratificada ajuda a manter proporções parecidas das classes em cada fold.

Resumo da aula

Validação cruzada é uma estratégia para avaliar modelos de forma mais confiável.

1. Não basta treinar

Precisamos avaliar o modelo em dados que ele não usou para aprender.

2. Uma única divisão pode enganar

O desempenho pode depender da sorte na separação treino/teste.

3. Cross Validation reduz esse risco

Usamos várias divisões e calculamos um desempenho médio.

Ideia central: medir generalização.

Exercícios de fixação

Questões rápidas para verificar se os principais conceitos foram compreendidos.

Exercício 1

Explique, com suas palavras, por que avaliar um modelo usando os mesmos dados utilizados no treinamento pode gerar uma conclusão errada.

Resposta esperada: porque o modelo pode ter aprendido padrões específicos dos dados de treino. Assim, o desempenho medido nesses mesmos dados tende a ser otimista e pode não representar o comportamento em dados novos.

Exercício 2

Em uma validação cruzada com 5 folds, quantas iterações são feitas? Em cada iteração, quantos folds são usados para treino e quantos para teste?

Resposta esperada: são feitas 5 iterações. Em cada uma, 4 folds são usados para treino e 1 fold é usado para teste.

Exercício 3

Você treinou dois modelos usando 10-Fold Cross Validation. O Modelo A teve F1 médio de 0,78 e o Modelo B teve F1 médio de 0,74. O que ainda seria interessante observar antes de escolher o Modelo A?

Resposta esperada: seria importante observar a variação dos resultados entre os folds, o tipo de erro cometido por cada modelo, a matriz de confusão, o custo dos erros, a interpretabilidade e se a diferença é relevante no contexto do problema.
